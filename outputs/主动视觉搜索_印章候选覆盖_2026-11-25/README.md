# 100 万像素内的档案印章与正文取证

本轮把已付费的月份线索用来给候选框排序。13 个回归条件里，严格年份 **5/13 → 7/13**，日期 **4/13 → 6/13**，正文 **5/13 → 5/13**，联合 **3/13 → 4/13**。另用两份新原件实测，四个条件的严格年份、日期、正文和联合仍分别为 **2/4、2/4、1/4、1/4**。新方法在回归中修复了错页和年月日粘连，独立样本还没有显示命中率收益。

## 先跑一个真实工单

在本目录打开终端。这个工单把 Cowell 干扰页放在前面，程序应在 Griffith 页标出收件日和对应正文。输出开头是核验结论，JSON 还包含每次实际送入 OCR 的裁剪范围、尺寸、原词、坐标、像素和输入摘要。

~~~sh
out=$(mktemp -d)
old=../页底印章年份复读_2026-11-18_晚间
sh run.sh query "$old/data/cowell.png" "$old/data/griffith.png" \
    --date 'AUG 26 1970' --text 'Thanking you I remain' \
    --output "$out/griffith.json"
~~~

实测输出 `verified`，两个字段均位于第二张图，实际支出 938,863 像素。11 次 OCR 的输入摘要与实验轨迹逐次一致。加 `--policy spare-stamp` 可用上轮规则。入口沿用项目 3.2 的本地 PNG、JPEG、WebP 与 PDF 输入。大卷宗先抽出所需页，方便保留原始扫描尺寸。[实际运行导出](demo-griffith.json) · [查询入口](run.sh)

## 算法改了哪一步

先执行水平搜索，完整计入其预览和 OCR，对已取得的正文保留原词和词框。页底剩余预算用于以下步骤。

1. 从已付款的 OCR 提取靠近页底的月份线索。按是否看到目标日号、月份相似度及 OCR 置信度排序。比如 Tweed 的 `seps` 可以提示寻找 `SEP`。年份形状仍是备用线索。查询的年份只参与最终日期匹配。
2. 候选去除重叠后最多留两处。存在两个候选时，首选最多拿 65% 的剩余像素。已找到正文时只补查同一页。预算不够或原日期已核实就停止。
3. 对候选读整行，按 OCR 词框缩小到年份，必要时再尝试减细笔画的整行。证据要求真实独立四位词和精确月日，复用同一页、几何相邻和合法日历日期的约束。返回时可在轨迹中分别定位年词与月日的来源。

两种策略共用 Tesseract.js 7.0.0、同一英语权重和水平搜索。坐标在原扫描像素空间。严格定位要求正确文本、正确页、框交并比至少 0.30 且覆盖人工框至少 48%。联合题要求正文与收件日都满足这些条件。[规则冻结稿](protocol.md) · [候选与预算代码](routing.py) · [实测与回放代码](run.py)

~~~

命令先检验冻结摘要，再用已保存的 OCR 复算动作和得分。随后从原扫描重新执行 13 个回归条件、4 个新件条件的两种策略，与存档逐行比对。两种策略共用完全相同的先行搜索，在计费表中分别扣除全额。装有项目 3.2 依赖的机器可直接启用，`VISUAL_SEARCH_PYTHON` 和 `VISUAL_SEARCH_NODE` 可指定运行环境。保留本目录与上轮及 3.2 的相对目录结构。[回归回放核验](regression-replay.json) · [独立回放核验](holdout-replay.json)
