# 印章候选定位与局部放大 · 2026-11-17

复用两张已见的真实档案扫描和 11 道冻结题（正文 5、页边 4、跨页组合 2），均读取同一份长边 2400 像素图像。内容与来源见 [冻结扫描清单](../真实扫描评测_2026-11-17/manifest.json)。参考框只用于评分及单列的已知位置诊断。当前数据来自两个已参与故障诊断的页面。

## 候选与预算

每页左右各取 15% 宽，去掉最外侧 1.5% 后缩到 240 像素高并转灰度。条带内将亮度低于第 75 百分位减 22 的像素视为墨迹，去掉墨迹占比超过 30% 的列，减轻纵向边框的影响。沿条带取页高约 16% 的窗口，以约 4% 页高为步长。候选分数等于窗口墨迹占比乘含墨行占比，以页 ID、侧边、纵坐标打破同分。选前四个，同页同侧的窗口相互覆盖超过 45% 时去重。候选打分与排序不读问题或参考框。

先扣除实际预览像素。再把余量的 65% 设为候选 OCR 上限，逐个均分当时剩余候选额度，局部最高用输入的原始分辨率。左侧顺时针 90°、右侧逆时针 90°。OCR 词框反变换到原页，然后使用旧精确短语匹配和日期归一化。证据齐时提前停。未完成的字段用余量走正文优先。分组全都用同一 OCR，worker 预热后按题轮换执行顺序，无 OCR 缓存。耗时含预览和调度，排除文件加载和预热。

运行测量把低分辨率预览与 OCR 像素都计入新方案的总预算。基线没有单独预览。原始轨迹包含每次预览尺寸、阈值和开销，完整候选分数与去重决定，每次 OCR 窗口、方向、实际输入尺寸、原文转写及回投坐标。候选定位以覆盖程度单列诊断，严格通过仍要求答复和每个字段的原页与锚点框正确，IoU 至少 0.30 且参考框覆盖至少 48%。

## 复跑

在本目录用具备项目依赖的 Python 3.11+ 执行。实验脚本从相邻目录取冻结图像、清单与 3.2 代码。题目和预算摘要、图像字节由运行器校验。

~~~sh
shasum -a 256 -c frozen.sha256
python3 -B check_dates.py
python3 -B check_geometry.py
python3 -B run_scan.py --smoke --output smoke-replay.json
python3 -B run_scan.py --output results-replay.json
~~~

protocol.json 和 frozen.sha256 保存实测前锁定的参数与代码。reference-assisted.json 复制上一轮已知位置诊断，印章从人工参考框扩大取图，局部词框 IoU 为 0.823。该结果单列，不计入本轮各策略评分。灰度读图限于页侧缩略图，当前实验没有为页首批注增加候选，相关命中仅可能来自正文回退。策略在本目录单独交付。

## 印章读图与失败分层

scan17-08 在两档都救回。侧边预览共 22,080 像素。第 13 页左上窗口是全局第 1 名，其 OCR 没有目标日期。第 26 页右侧窗口的墨迹得分排全局第 3，第 2 名与已选窗口重合被抑制。第 3 名是第二次实际观察，原页框 [1388, 400, 1609, 780]，覆盖日期参考框，旋转后以 380×221 像素送 OCR。固定条带在 100 万档为 782×63，返回 “(Gans”。新窗口 OCR 返回 “MAR2 3 1971”，规范日期是 1971-03-23，实际词框 [1478, 567, 1519, 717]，与参考框 IoU 0.823。两次 OCR 共 173,660 像素，含预览为 195,740。结果来自无标注调度。

scan17-10 同时救回另一页正文和该印章日期，两处证据分别来自正文回退与第 3 名窗口，两档均通过。这个组合题与单题共享同一处印章，因此两道新增通过只代表救回一处独立页边证据。scan17-09 的环形机构名位于同一窗口，OCR 仍输出碎片，精确词锚未通过。两个手写页首批注继续未解。与正文优先比较，两档通过的正文题完全相同，但正文题总像素因探查页边而增加。页边和组合题提前停带来的节省使 160 万档总体总像素少 9.3%；100 万档总体多 4.8%。当前耗时仅为一次本机运行的描述值。
