# 在 100 万像素内核对档案信函的日期和正文

新策略在两份未参与调参的档案上完成了 **3/10** 个联合定位条件，上一轮标题优先策略为 **0/10**。平均实付像素从 918,742 降到 783,440，下降 14.7%。三个新增通过项都依赖 Nixon 信上同一个横排日期。Diggs 信上的底部收件日期仍未读全。可从[逐题结果](heldout-rows.tsv)查看一次查询花掉的像素、两个词框的 IoU 及走过的分支。

## 改动与适用范围

1. 搜索器在原图顶部 1.5% 至 42% 处读取横排内容，在底部 73.5% 至页末寻找收件戳。在送入 OCR 的付费分辨率上校正纸面明暗差。顶部和底部首读分别分配扣除侧边预览后预算的 32% 和 22%，多页时按页分配，找到目标日期即可转向正文。[搜索代码](letter_search.py)
2. 已读的月份、日或年可以提出单行裁剪。复读使用原扫描，证据必须有可组成合法公历日期的实际 OCR 字符，日期词框只合并对应单词。支持英文十二个月的全拼、缩写、年-月-日和收件戳中常见的分隔写法。正文已有充分词线索时也可以提前复读。[日期代码](dates.py) · [日期与词框检查](test_dates.py)
3. 水平读取失败后，可继续检查旋转侧窗及全局候选。评测从 OCR 后端记录每次实际输入宽高、模式、原始词和词框，与调度器的逐步账本核对。单行放大按放大后的实际尺寸收费。独立集旧、新策略最高实付分别为 999,925 和 925,552，都在 100 万像素内。[评测程序](evaluate.py)

另用已见的两道竖排日期联合题检查兼容性，未并入独立数据。马歇尔页的单页及干扰页条件在旧策略均通过，新策略两次都读到了日期，却漏了正文标题。第 13 和 26 页的真正跨页联合题两策略都通过，新策略耗用 702,315 像素，旧策略为 428,498。已有竖排取证工作流可以显式使用 `--policy heading-first`。本轮信函优化的收益集中在横排签发日期。[兼容性轨迹](legacy-controls.json)

## 运行与复现

从本目录运行。使用项目自带的英文 OCR 权重和本机 Node 24.22.3、Tesseract.js 7.0.0、Python 3.12.14，无需联网。Python 依赖为 NumPy、Pillow 和 pypdfium2，与现有 3.2 项目相同。

```sh
py="${VISUAL_SEARCH_PYTHON:-$HOME/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3}"
out="$(mktemp -d)"
"$py" -B search.py data/nixon.png --date 'August 9, 1974' \
  --text 'I hereby resign the Office' --output "$out/example.json"
shasum -a 256 -c policy.sha256
shasum -a 256 -c holdout.sha256
"$py" -B test_dates.py
"$py" -B evaluate.py development "$out/dev.json"
"$py" -B heldout.py "$out/heldout.json"
"$py" -B heldout.py "$out/repeat.json"
"$py" -B verify.py --development "$out/dev.json" --heldout "$out/heldout.json" --repeat "$out/repeat.json"
"$py" -B summarize.py "$out/heldout.json"
"$py" -B summarize.py --rows "$out/heldout.json"
"$py" -B compatibility.py "$out/legacy-controls.json"
```

两份独立档案的 20 条配对轨迹已经完整复跑。除耗时外，实际 OCR 词、证据框、动作顺序和像素支出逐项一致。开发集旧策略的 12 项结果也与上轮记录一致。[核验结果](verification.txt) · [独立复跑轨迹](repeat.json) · [直接查询示例](example.json)
