# 从初版到 3.0

初版教材里的三件事可以原样带过来。观察是一次裁剪加缩放，预算按观察图的面积扣，证据坐标要从观察图投回原图。3.0 把它们放进一次跨页任务，新增了页选择、字段状态和多证据验收。

## 工单一 · 跟踪两页距离

~~~sh
sh run.sh query --example hubble-distance --output local/hubble.json
~~~

1. 打开 [任务 JSON](../data/hubble-task.json)，看字段 A 和 B。两个锚点之后都只需找近处的第一个数字。任务中没有页码或答案。
2. 读 [pdf_index.py](../search_agent/pdf_index.py) 的 `index_page` 和 `candidate_boxes`。输入是 PDFium 的文字页、渲染图坐标转换器和锚点词序列。函数把字形位置投影到原始页，只返回候选框。用结果中的 `pdf_candidates` 查看两个字段各有几个候选。B 有两个候选，其中一个位于第 1 页，仍要经过 OCR 才能决定。
3. 读 [scheduler.py](../search_agent/scheduler.py) 的 `hybrid_run` 与 `Ledger.buy`。调度器按候选生成小裁剪，把同页同范围同大小的观察记一次，再以 OCR 行里的确切锚点做核验。对照 `steps` 的三次调用，检查 `25950 + 16100 + 16050 = 58100`。第二步没有供给最终证据，仍然收费。
4. 读 [task.py](../search_agent/task.py) 的 `field_matches` 与 `answer`。输入是 OCR 原始词和坐标，先精确命中锚点，再按方向及词窗选择数字，用 `Decimal` 保存数值。最后用两处证据计算 `86 − 200 = −114`。在 JSON 里找对应 `anchor_box`、`value_box` 和 `view`。

练习。保持 A 不变，将 B 的锚点改成不存在的词组。先预测 `status`、`answer` 及证据数量，再运行自己的任务文件。参考答案是 `partial`、`null` 和一条 A 的证据。系统会把剩余预算用于寻找 B，像素可能高于原来的成功运行。

## 工单二 · 纯图像、数字核验和失败分析

~~~sh
sh run.sh query --example operations-difference --strategy hybrid --output local/operations.json
sh run.sh query --example operations-difference --strategy uniform --output local/operations-uniform.json
~~~

1. 结果应显示 `pdf_candidates` 中 A 和 B 都为 0。进入 `adaptive_run` 后，初读扫描每一页，共享总预算。对数值先保留一次暂定识别，再决定是否对原行做小范围核验。
2. 找到 `confirm:A` 和 `confirm:B`。检查证据分别回到巡检第 5、2 页。数字为 `1330` 和 `−6973`，差值为 `8303`。用工作台打开两处实际 OCR 图，辨认 B 的负号。
3. 对照整页均分的每次开销。打开 [评分实现](../search_agent/evaluation.py) 的 `hit_ok` 和 `check`，确认数值相等、页码相等、框重合是分别检查的。在失败任务里可以定位到召回失败、数字读错或定位框错误。

练习。在工作副本里把 `confirmation_spec` 的核验上限从 `150_000` 改成 `80_000`，先用 `--split dev --budget 2600000` 跑改前和改后。记录严格通过、平均像素、OCR 次数，并抽查一条数字错误的轨迹。参考答案的判断标准是先比较开发集的准确率和像素，定位变化来自哪一步。把用在开发集上的决策固定后，再跑一次留出集，保留退步结果。

## 简历面试可以讲清的内容

做完两个工单后，按自己实际完成的工作记录三件事。写清输入和证据约束，指出哪个消融说明 PDF 路由有效，再用一条失败轨迹解释它在扫描版或密集标签上的边界。想形成个人贡献，可以选定一个独立文档集或一种失败模式，提交自己的复现、改动、对照结果和结论。
