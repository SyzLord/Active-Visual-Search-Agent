按物理原件计，至少一个条件通过的年份为 6/8 → 6/8，日期为 6/8 → 6/8，正文为 3/8 → 3/8，联合为 2/8 → 1/8。页底平均支出 249,563 → 261,428。最高全题支出分别为 996,673 与 999,916。两策略分别调用 134 与 138 次 OCR，其中追加 23 与 27 次。[逐题账本与候选页](results/rows.tsv) · [OCR 原词及原图坐标](results/raw-evidence.json)

- **D2 双页挽回，单页丢失。** 旧策略双页先复读 Griffith，后来在正确页识别 `JUL 15 1663`。新策略直接重读目标页，识别 `JUL15 1963 jj`，总开销少 26,340 像素。单页旧策略读到 `JUL15 1963`，新策略两次误读 `JUL 15 1563`。
- **N4 单页读出年份，日期与联合失效。** 旧策略识别完整 `MAR 5 1970`。新策略在正确页读成 `MAR § 1970` 和 `WAR S 1970`，年段独立读出 `1970`。缺少可核验的完整月日。
- **N1 手写原件，选对页仍没读全。** 单页新策略读成 `JUN S 1971`，年段读出 `1971`。双页两种策略都只复读 Griffith。整体两种策略均有 4/8 个双页条件只给干扰页分配附加像素，双页正文均为 0/8。

本组来自三个历史卷宗，入组要求人能看到页底四位年份。样本内有重复年份及相近版式。这样的证据能说明这批扫描上的收益与退化，跨档案的联合准确率仍待扩大验证。

## 在 GitHub 检出的目录复跑

需要 Python 3.11+、Node.js 18+、Pillow、NumPy、pypdfium2 和 Tesseract.js。先按 [批量 CLI 安装说明](../../batch/README.md)配置环境。从本目录执行下面的命令。可通过 `VISUAL_SEARCH_PYTHON`、`VISUAL_SEARCH_NODE` 指定解释器。

```sh
sh reproduce.sh replay
sh reproduce.sh live
sh reproduce.sh prepare
```

`replay` 离线复算存档的 32 条轨迹和 272 个 OCR 输入摘要。`live` 从扫描图重新识别并比对逐题表。`prepare` 从 3 份入组 PDF 重建并核对扫描、任务清单和标注图。实验分两批写入的 SQLite 数据库和原始证据均在 [results](results/)。

本目录收录 8 页新扫描、1 页固定干扰图、3 份实际入组的原始 PDF。其余 3 份仅在筛选时查阅的卷宗保留在 [来源清单](archive-sources.tsv)中。原冻结表保存在 [original-locks](original-locks/)，公开版用 [publication.sha256](publication.sha256) 校验收录文件，[engine.sha256](engine.sha256) 校验 GitHub 检出中的原批量引擎。
